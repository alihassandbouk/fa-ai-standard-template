### Decisions
- Official package through the React adapter `platformscode-new-react` (+ `@platformscode/core`), never a vendored `@ds` copy, never NDS-vanilla, nothing Angular or MOI. The scoped `@platformscode/react` is dead (depends on core as `workspace:*`).
- Rules in the always-loaded `ui-rules.md`; how-to in the skill; props from the installed type file and the Storybook, not a copy. No PNGs, nothing hosted in Notion.
- Tailwind arranges only; anything with a colour is a DGA component; no DGA colours in the Tailwind theme.
- Next.js: the skill gives the client entry module only; page layout is each project's.
- ESLint `no-restricted-syntax` rule against raw button, input, select, table, dialog, added by the skill on first use, not by the scaffold.
- No ADR in this repo (it keeps none); reasoning is in the personal diary and the README row.

### Problems solved
- Icons blank with the official `setAssetPath(origin + '/assets/')` → the component requests `assets/svg/…` relative to the base, so the path doubled → base is the site root `'/'`.
- Tailwind `p-6`, `flex`, `mx-auto` silently ignored next to DGA → DGA's stylesheet is an unlayered reset and sets `html { font-size: 62.5% }` → `@import "tailwindcss" important;` and `:root { font-size: 100% }`.
- `this.onBlur is not a function` on first blur of a text input → the component calls handler props unguarded → always pass `onBlur`, `onChange`, `onInput`.
- Lint check did not fail in a fresh Vite 8 app → the template's lint script is oxlint, which ignores selector rules → `"lint": "eslint src"`.
